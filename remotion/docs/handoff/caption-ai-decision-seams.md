The caption pipeline splits responsibility: **Claude owns CONTENT, the template owns LAYOUT.**

- **Claude (enrich.mjs)** decides: spelling/punctuation fixes, dialect/code-switch preservation, **caption breaks** (one complete idea per caption, overflow words pushed to the NEXT caption — never padded to fill), per-word **emphasis**, and per-word **variant** (base/punch/elegant). Output: `<name>.enriched.json`.
- **Caption breaks are MEANING-ONLY and SHARED (commit `fd505d5`, 2026-08-10 — supersedes the per-shape model):** `--shape` is GONE, as are all words-per-line caps. ONE Claude call decides caption breaks for the whole video and returns a FLAT word list per caption (no `lines`); every template uses that same answer, so a caption is the same words in every template. **Code** then line-wraps into each template's shape (`TEMPLATES` map in enrich.mjs: hormozi 2 / hormozi2 2-exact / gadzhi 2-exact / shiny 3 / kinetic 3 / minimal 1) via `splitInto`, brute-forcing every split point and scoring with `BINDS_NEXT` (never end a line on an article/preposition/auxiliary — Latin + Arabic), a modifier-suffix rule (keeps "engaging reels" whole), a comma bonus, and width balance measured in CHARACTERS not words. The script writes ALL variants itself — the old hand-merge step is gone (that step is why `variants.hormozi2` had been silently missing). Validation now only checks what code can verify: word indices in order, no empty caption, no sentence ending mid-caption.
- **Why counts were removed:** they were a poor width proxy AND they leaked into the meaning decision (Gadzhi's 5-word cap pushed "you" into the previous caption). Templates already measure real rendered width in the DOM and shrink to fit, so fitting is physics, not counting. Chosen trade (user decision): a long idea SHRINKS rather than being broken at a worse point.
- **THREE levels, not two (2026-08-10):** CAPTION (Claude, meaning, shared by every template — the stable identity) → SCREEN (code, per-template, capacity-driven) → LINE (code, per-template). A caption is usually one screen, but a template whose text is too big to hold it shows the SAME caption across consecutive screens. Splits happen strictly INSIDE a caption; no word ever crosses a caption boundary, which is what keeps per-block template switching safe. Segments now carry `ideaIndex`/`part`/`parts`; grouping by `ideaIndex` rebuilds Claude's captions exactly (asserted in the layout test).
  - Layout half lives in `remotion/layout.mjs` (split out of enrich.mjs), imported by enrich.mjs AND by `remotion/relayout.mjs` — the latter re-lays an existing `.enriched.json` for every template with NO Claude call, so restyling a template updates a whole library for free (`node relayout.mjs "public/*.enriched.json" --overwrite`).
  - `layoutFor` is a `flatMap` now, not `map`. `splitInto(words, n, minPer)` is the ONE primitive used at both levels (screens and lines) — same `BINDS_NEXT`/comma/balance scoring; `minPer` blocks orphan screens.
  - `charsPerLine` is DERIVED from how a template actually renders: `fitFraction / ((fontSizePct/100) * advance)`, anchored on Gadzhi (26 chars @ 6.63pct/0.9fit ⇒ advance 0.52 normal, 0.45 condensed). Hormozi 2 was inheriting Gadzhi's 26 while rendering at DOUBLE the glyph height (13.5 vs 6.63 fontSizePct) — its real capacity is 15. That single wrong number was the whole "Hormozi 2 doesn't fit" bug.
  - `OVERFLOW_TOLERANCE = 1.1` — a caption may run 10% past a screen budget before splitting, because every template shrinks an overrunning line and a ~10% shrink is invisible. Without it, minimal split 4 captions into 6 on a 1-char overflow.
  - Measured on sample-video: hormozi2 4 captions → 7 screens; hormozi/gadzhi/shiny/kinetic/minimal all unchanged at 4. Verified in Studio (7 vs 4 `<Sequence>`s; `YOU / CAN CREATE` then `ENGAGING REELS / AND TIKTOKS`). The renderer needed NO change — `enrichedToBlocks` already derives each block's time range from its own words.
- **Per-segment template switching = the differentiator, STILL NOT BUILT.** The above is "Part A" (the foundation — stable block identity across templates). Part B still to do: a `template` field per caption, click-a-block UI, rendering contiguous same-template runs as separate `<Sequence>`s instead of one `singleSurface`, and per-run font sizing so a big template can't shrink the others.
- **Manual screen-break override = NOT BUILT.** The scorer gets close but not always to the user's preferred point (on `you can create engaging reels and TikToks` it picks `you can create` | `engaging reels and TikToks`, keeping the adjective with its noun, rather than the user's balance-driven `you can create engaging` | `reels and TikToks`). Needs: Hormozi 2 added to `EDITOR_STYLES` (it is not documentDriven in the editor today), a move-word-across-screen-break op, and an override stored per (ideaIndex, template) so tweaking Hormozi 2 cannot change Gadzhi — Gadzhi has no such break.
- **Per-caption grouping model (FINAL — supersedes the earlier "hybrid autoGroup toggle"):** there is NO global words-per-line / lines-per-segment slider and NO autoGroup checkbox. `autoGroup` + `wordsPerLine` were REMOVED from Hormozi's schema/type/defaults/Root. Auto (Claude's doc) is just the starting state; freedom is per-caption. Templates render the caption document's lines EXACTLY as authored (`enrichedToBlocks`); a hardcoded 3×2 count-grid (`FALLBACK_WORDS_PER_LINE`) is only a raw-ASR fallback when no document exists.
- **Caption document data model (Phase 1 DONE):** `types.ts` has `CaptionDoc = {language, segments, translation}` and `EnrichedSegment` now carries optional `id` + `edited` (the editor selects by `id` and pins `edited` captions so a Claude re-run won't clobber them). The enriched JSON IS the editable source of truth.
- **N-line color swap (Phase 1 DONE):** `HormoziSegment` takes `lineStartFrames: number[]` and the accent steps through ANY number of lines (activeLine = last line whose start frame is reached). Default auto output is 2 lines; a user may set a caption to 1 or 3 (verified rendering 3-line swap line0→1→2 on the English sample).
- **User editing UX (confirmed decisions, ROADMAP — Phase 2/3 NOT built):** density = per-caption only. Move-word freedom = "click a word → move to next caption / break line here / pull from next line" buttons in the SaaS web editor (the `@remotion/player` playground app), NOT drag-drop, NOT Remotion Studio. Phase 2 = editor UI (word chips, move/split/merge, 1/2/3 line control, emphasis toggle). Phase 3 = per-caption "AI re-segment" button (Claude redoes one caption on demand).

Swappable helper functions still exist (`decideEmphasis`/`decideLineAlignment`/`decideSentenceSplit`) as the no-Claude fallback path, but the live path is the enrich JSON.

Engine wiring: `index.tsx` loads `.enriched.json`, keeps `EnrichedSegment[]` in state, passes `segments` prop to the single-surface PageComponent (Shiny/Hormozi/Highlight). Verified working on the English `sample-video` (Hormozi shape): "Using Remotion's" / "TikTok template," with "you can" pushed to the next caption, top→bottom color swap intact.

**Why:** this is the finalized division of labor for the caption engine. Part of [[captions-remotion-architecture]], [[transcription-architecture-decision]], [[caption-still-text-preference]], [[vemcp-saas-goal]].
